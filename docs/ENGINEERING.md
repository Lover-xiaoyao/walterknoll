# 本项目怎样应用生成式软件工程

项目切换到 Walter Knoll 后，先读取用户给出的目录说明、ZIP、十页截图、本地 jyy 笔记及课程官网，再把可观察结果写入 SPEC.md。旧项目不覆盖，新仓库从空仓库独立开始。

本地学习资料包括 GB18030 编码的 study.md、课程梳理、AI-Native Software Engineering Playbook 与记录工具示例。示例的报名系统规则不适用于这个静态网站，因此没有复制报名业务或元数据审计系统。

| 课程思路 | 本项目中的实际做法 |
| --- | --- |
| Intent → Spec → Implementation | 意图是官网复刻；十页表固定范围；SPEC.md 明确交互和教学边界 |
| 版本是可恢复快照 | 分别提交原始骨架、素材与数据、完整实现、验证与说明 |
| 对变化选择合适的表示 | 导航/页脚使用一份片段；CSS 四层；列表由统一产品索引生成 |
| 事实与派生显示分开 | catalog.json 保存产品事实，筛选计数、分页、搜索结果在浏览器中计算 |
| 执行反馈胜过自评 | Playwright 实际操作筛选、分页、Tab、色卡、表单；截图检查两个视口 |
| 证据有范围 | 记录本地浏览器结果与未覆盖内容，不把本地测试描述成官网后端或线上部署成功 |

## 资料与实际实现的取舍

- ZIP 中九个内页为空，因此补齐页面内容，而不是保留占位文字。
- 当前实测首页白底顶栏覆盖 Hero，修正旧文档的透明顶栏说明。
- 原官网商业字体没有作为资源下载；使用系统字体替代并记录视觉差异。
- 官网产品页当前返回十类；分工说明的十一类中含旧的 Exhibition pieces，本轮没有编造展品数据。
- 杂志列表不编造发布时间；保留来源分类、标题、图片和官方文章入口。
- 可持续页面展示可追溯年份和原则数量，没有使用分工文件的“98% 可回收”等示例值。
- 联系与订阅的范围是界面与验证；成功结果明确表示没有发送。

## 关于 REA

已查看 [morluto/rea](https://github.com/morluto/rea) 的用途与安装说明。这个网站通过公开 DOM、页面数据和浏览器截图即可观察，现有 Playwright 足够完成本轮页面与交互分析，因此没有额外安装 REA 或改变全局 Agent 配置。
